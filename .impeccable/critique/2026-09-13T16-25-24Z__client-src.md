## Design Specificity Verdict

**Start here.** The *jobs* are PlusQueue. The *look* is a category-interchangeable Tailwind clinic dashboard. Swap the copy to another clinic vertical and almost nothing visual would break.

**LLM assessment:** Official name PlusQueue and official mark `brand/plusQueue-logo.png` do not appear anywhere under `client/`. Login lockup is Lucide `Activity` in a `bg-blue-50` square plus the title “Pediatric Clinic Queue System”. Staff shells say “Secretary Portal” / “Doctor Portal” / “Admin Portal”. Document title in `client/index.html` is `client`. `index.css` is a single `@import "tailwindcss"` — no tokens, no type scale, no logo-derived palette. All four roles wear the same costume: `h-screen` + `w-64` white sidebar + `bg-gray-50` + `rounded-2xl`/`rounded-3xl` cards + Lucide + `font-black` numerals + default `blue-600`.

What *is* authored for this product: the boarding-pass QR ticket, the parent “My Queue Number / Patients Ahead” pair, the secretary Validate FAB, and the waiting-room Queue Monitor. Those compositions would not survive a category swap. Everything around them would.

**Deterministic scan:** `impeccable detect --json client/src` returned **39 warnings**. **38 are false positives.** 33× `border-accent-on-rounded` are loading spinners (`animate-spin rounded-full … border-b-2`). 5× `gray-on-color` join mutually exclusive Tailwind `hover:`/`disabled:` variants. **1 real hit:** `bounce-easing` on `QueueMonitor.jsx` (`ChevronDown` with `animate-bounce` when waiting queue length > 10). Detector did not see the identity gap, 9–11px labels, missing focus rings, or click-only cards. Unused Vite `App.css` was not flagged because detect is markup-only and `main.jsx` never imports it.

**Visual overlays:** No reliable user-visible overlay. This session has no browser MCP (no tab, evaluate, or script injection). Live-server and `detect.js` were not started.

## Overall Impression

The product already knows a pediatric clinic: a ticket, a desk scanner, a consultation lock, a waiting-room board. The interface does not. It looks like a competent student-admin template — cool gray, interchangeable portals, heartbeat icon — then suddenly becomes a navy boarding pass. That split is the whole problem.

The single biggest opportunity is to make **the ticket** the product object: one identity, one turn, one next action — then let each role’s layout get denser or calmer around that object. Do not wrap this in another generic SaaS dashboard.

## What's Working

1. **Parent live-queue composition** (`pages/parent/Dashboard.jsx`): giant ticket number, patients ahead, Now Serving, and a “You” row with a left rail. This is the only parent screen that already feels like a queue product.
2. **Digital arrival pass** (`pages/parent/QRTicket.jsx`): perforated boarding-pass language, huge reservation code, present-this-to-the-secretary copy, post-check-in “Arrival Confirmed.” High-stakes artifact with a point of view.
3. **Role-aware Operate bones:** parent 4-tab phone nav; secretary raised Validate FAB; Queue Monitor as a room-scale board; doctor consultation lock (`canSendToDoctor` only if first + checked_in + room empty). The structure knows the clinic. The skin does not.

## Priority Issues

### [P0] Reserve commits a slot before the parent finishes
- **What:** `ReserveQueue.jsx` `handleReserveClick` calls `createReservation` then opens “Select Patients.” Cancel in that modal runs `handleCancelReservation`. Incomplete child info later blocks secretary check-in.
- **Why it matters:** One active reservation per parent per clinic date. A distracted parent who backgrounds the app now owns a slot they did not confirm, may not have named the right child, and can be turned away at the desk.
- **Fix:** Choose child + concern *before* the write. One confirm: “Reserve for {child} at {branch}, {date}.” Success goes to the ticket, not a “Queue Position” dead-end. Same `createReservation` call; different order. Do not change slot rules.
- **Suggested command:** `/impeccable shape`

### [P1] Status language sells the wrong object
- **What:** Permanent `queueNumber` is presented as “My Queue Number” / “Queue Position.” Turn lives in `queueOrder` / “Patients Ahead.” Parallel vocab: Validation Open, Waiting for Window, Request Check-In, Validate Reservation, With Doctor, In Consultation. Two badge systems disagree on color (checked-in is green in one, indigo in another).
- **Why it matters:** Anxious parents will treat #7 as “seventh in line.” After a penalty they still see #7 and think nothing changed.
- **Fix:** One parent sentence: **“Ticket #7 · 3 families ahead.”** Staff keep ticket vs turn. Parent UI says “check-in open” / “arrive by {time},” never “validation window.” One badge component.
- **Suggested command:** `/impeccable clarify`

### [P1] Desk tasks are split across the wrong surfaces
- **What:** Real check-in is `/secretary/validate` (QR + 6-char). ManageQueue “Request Check-In” only sends a reminder. Send to Doctor lives on the first checked-in card. **Walk-in is opened from `secretary/Profile.jsx`,** next to logout.
- **Why it matters:** The desk loop is arrive → verify → send. The UI makes that three mental models and hides walk-in with account settings.
- **Fix:** Validate stays the scanner. ManageQueue header gets next arrival + walk-in. Rename “Request Check-In” to “Remind to arrive.” Confirm Send to Doctor and Penalize. Do not change eligibility rules.
- **Suggested command:** `/impeccable layout`

### [P1] WCAG 2.2 AA is named as the floor and is not shipped
- **What:** `focus:outline-none` without a replacement ring on parent chrome, QR actions, password toggles. My Reservations / ManageQueue / doctor consultation cards are click-only `div`s. 9–11px uppercase labels. Unlabeled toast dismiss and show-password. Dialogs without `aria-labelledby` or focus trap. `index.html` title is `client`.
- **Why it matters:** Primary users are on phones, often one-handed. Keyboard and screen-reader users cannot complete reserve → ticket → QR as first-class tasks.
- **Fix:** Global `:focus-visible` ring. Cards as `Link`/`button`. 14px minimum UI type. Name every icon button. Focus-trap dialogs. Title = PlusQueue.
- **Suggested command:** `/impeccable audit`

### [P2] Identity and visual world are a template
- **What:** No PlusQueue wordmark or logo. Lucide Activity as a fake mark. Tokenless utilities. Four “Portals.” Leftover `App.css`.
- **Why it matters:** First-run trust for a pediatric clinic. Parents and staff do not share a recognizable product. This is also why the UI reads as generic AI-SaaS.
- **Fix:** Official mark + name at auth and all four shells. One component vocabulary. Delete unused `App.css`. Tokens in `index.css`. Logo blue for identity/primary; coral only for “your turn”; yellow only for “almost.”
- **Suggested command:** `/impeccable shape`

## Persona Red Flags

**Casey (distracted mobile parent):** Reserve is a mid-card button, not a thumb-zone primary. Tapping it writes the daily slot immediately. Home can open with a push-permission banner above the ticket. My Reservations cards are `div onClick`. 9px “My Queue Number” fails a one-handed glance.

**Jordan (first-timer):** Login name is not the product they were told to install. Register is one wall (name, phone, OTP, email, password, confirm). `OnboardingStepper` is Verify Email → Add Child and pretends phone never happened. First success modal says “Queue Position,” not “here is your ticket.” No in-flow help for what happens at the clinic.

**Alex (secretary power user):** Check-in is not on Manage Queue. “Request Check-In” is a reminder with a check-in name. Penalize and Send to Doctor are one tap, no confirm. Walk-in is on Profile. Desktop Home embeds ManageQueue under stats — two queues, same session.

**Anxious parent (project-specific):** Large ticket # plus “Please wait for your turn” while “Patients Ahead” is the actual turn truth. Footer “Real-time updates may vary depending on internet connection” is a fear prompt. After a penalty the number stays; nothing says they were moved back. High-stakes notification types share the same rose `AlertCircle`.

**Sam (accessibility):** Keyboard cannot activate reservation cards or several staff cards. Missing focus rings. Contrast risk on `text-gray-400` / 10px on gray, `text-blue-200` on navy. Password toggle and toast dismiss have no accessible name. ConfirmationModal is `role="dialog"` without a name.

## Questions to Consider

- If the official object is a ticket (permanent #) plus a turn (people ahead), why does every parent hero lead with the ticket and call it a queue number?
- Why does tapping Reserve Slot spend the family’s only slot for that day before they name the child?
- If the secretary’s job is arrive → verify → send, why is walk-in on Profile and check-in a different route from Manage Queue?
- What would a parent who has never heard “validation window” need to see to know when to leave the house?
- If this is PlusQueue, why does the first screen still introduce a nameless “Pediatric Clinic Queue System” wearing a heartbeat icon?

## Proposed design direction (before implementation)

This is a recommendation, not a locked world. Implementation stays blocked until you choose.

**Refuse:** generic SaaS dashboard (sidebar + KPI tiles + indigo). Refuse cartoon pediatric ward (mascots, balloons, candy pastels). Refuse polishing the current Tailwind portal costume.

**Thesis:** A digital clinic ticket desk. Quiet paper-and-ink surfaces. PlusQueue mark at identity points. One ticket, one turn, one next action. Staff get denser instruments in the same language; parents get a calmer phone. Familiar Operate patterns, authored details.

**Physical scene (forces light, not dark):** Bright waiting room and reception counter, daylight plus clinic fluorescents, parents on phones, secretary standing at a desk, doctor in a consultation room. The UI should feel like a well-printed ticket and a clear counter display, not a monitoring wall.

**Color strategy — Restrained, with three named roles from the official mark:**
- Blue: identity and primary action
- Coral: “your turn” only
- Yellow: “almost / nearing turn” only
- Neutrals carry the surface. Semantic green/red stay for success/danger, not decoration.

**Type:** One highly legible sans for all UI (headings, labels, data). No display serif. No Inter / Plus Jakarta / DM Sans / Outfit default. Strong candidate when we typeset: a low-vision-friendly workhorse (e.g. Atkinson Hyperlegible or equivalent) because parents glance at this under stress; the reason is clinic readability, not “tech sans.”

**Shared language, different density:**
- **Parent (phone-first):** Ticket is the hero. Bottom nav. One primary action per screen. Copy in family language.
- **Secretary (desk):** Scanner + live queue as one workplace. Walk-in on the queue, not Profile. Denser lists, larger tap targets still.
- **Doctor (room):** Current patient at poster scale; waiting list secondary; pause/close labeled, never icon-only.
- **Admin (office):** Tables and filters, same tokens and chrome, not a third visual product.

**Keep from today:** role-split IA, QR boarding pass, parent Home pair once copy tells the truth, Validate FAB, consultation lock, Queue Monitor as a room board, empty states that point to one next action.

**Replace:** Activity-icon branding, Portal names, tokenless utilities, reserve-then-fill, dual badges, validation jargon in parent UI, walk-in-in-Profile, icon-only dangerous controls, leftover Vite CSS.

**Honest risk:** If we only restyle cards and keep “Queue Number” + reserve-then-fill + walk-in on Profile, it will still feel like a template with a new logo. The direction only works if ticket/turn language and desk IA move with the skin.
